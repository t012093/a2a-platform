# 仕様書（MVP）

## 1. ドメインオブジェクト
### 1.1 AgentProfile
- AgentCardの保存・検索用の内部表現

### 1.2 RFP
- 依頼内容（目的/KPI/予算/納期/参考LP/素材など）

### 1.3 Offer
- 見積・条件提案（価格、納期、修正回数、成果物、除外事項）

### 1.4 Contract
- 合意済み条件の固定化

### 1.5 Approval
- RFP/契約/支払いの承認記録

### 1.6 Payment
- エスクロー入金と支払いリリースの状態（PSP抽象化、MVPはStripe）

## 2. 状態遷移
### 2.1 RFP
- `draft` → `submitted` → `closed` / `cancelled`

### 2.2 Offer
- `proposed` → `revised` → `accepted` / `rejected` / `withdrawn`

### 2.3 Contract
- `pending_approval` → `active` → `completed` / `terminated` / `expired`

### 2.4 Payment
- `escrow_pending` → `escrowed` → `release_pending` → `released`
- 例外: `refunded`

## 3. A2A Task状態との対応
- 交渉中: `TASK_STATE_WORKING`
- 情報不足: `TASK_STATE_INPUT_REQUIRED`
- 合意成立: `TASK_STATE_COMPLETED`
- 拒否/終了: `TASK_STATE_REJECTED` / `TASK_STATE_CANCELLED`

## 4. 承認ルール（MVP）
- RFP送信前の承認（依頼側）
- 契約合意時の双方承認
- 支払いリリース前の依頼側承認

## 4.1 承認期限（MVP）
- RFP承認: 依頼側の承認依頼から **72時間**（期限切れは `draft` に戻す）
- 契約承認: 双方の承認依頼から **7日**（期限切れは `expired`）
- 支払いリリース承認: 納品通知から **7日**（期限切れは自動承認）

## 4.2 承認権限（MVP）
- 依頼側: `client_admin` または `client_approver`
- 代理店側: `agent_admin` または `agent_approver`
- 管理者: `platform_admin`（紛争時の上書き承認のみ）

## 4.3 承認リマインド（MVP）
### RFP承認（72時間）
- 依頼送信後 **24時間** で1回目
- 期限の **12時間前** で2回目
- 期限到達時に失効通知

### 契約承認（7日）
- 期限の **2日前** に1回目
- 期限の **1日前** に2回目
- 期限到達時に失効通知

### 支払いリリース承認（7日）
- 期限の **2日前** に1回目
- 期限の **1日前** に2回目
- 期限到達時に **自動承認通知**

### 通知チャネル
- メール + アプリ内通知（MVP）
- 重要イベントは監査ログにも記録

### 送信時間帯（MVP）
- 通知は **受信者（依頼側/代理店側）のタイムゾーン** を基準に **09:00–18:00** に送信
- 予定時刻が時間外の場合は **次の09:00** に送信
- 期限到達や自動承認などの **システム通知は即時送信**
- ユーザーにタイムゾーンがない場合は **所属組織のタイムゾーン** を使用
- 組織にもない場合は **UTC** を使用

## 4.4 通知設定（MVP）
### 組織単位の設定
- タイムゾーン
- 通知時間帯（例: 09:00–18:00）
- 週末送信（送る/送らない、**デフォルトOFF**）
- チャネル（メール/アプリ内）

### ユーザー単位の設定（任意）
- 組織設定をデフォルトとして上書き可能
- 権限ロールにより編集可否を制御

## 5. 権限（簡易）
- 依頼側: RFP作成/承認、契約承認、支払い承認
- 代理店側: 見積提出、交渉、契約承認
- 管理者: 監査ログ閲覧、紛争対応

## 6. 通知
- 重要イベント時（見積到着、承認依頼、支払い状態変更）に通知

## 7. データ保持
- 監査ログは最低1年保存
- 交渉ログ/契約は5年保持（将来要件）

## 8. 決済プロバイダ
### 8.1 方針
- PSPは抽象化し複数対応を想定
- MVPは Stripe Connect を採用
- 決済イベントは Webhook で同期

### 8.2 PaymentProvider
- `provider`: `stripe` | `paypal` | `adyen` | `other`
- 主要イベントは `payment_events` に正規化

## 9. 入金保持・リリース運用（MVP）
- 入金は「預り（ホールド）」として管理し、成果受領承認後にリリース
- レビュー期間: 納品通知から **7日**（カレンダー日）
- 自動承認: レビュー期間内に応答がなければ **自動承認 → リリース**
- 変更要求: レビュー期間内の差し戻しは **リリースを保留**（再提出で期間リセット）
- キャンセル時の返金率は契約条件（Contract）で明示（デフォルト: 作業開始前100% / 開始後・納品前70% / 納品後は紛争対応）

## 10. 商談拡張（A2A Extension）
- 拡張URI: `https://a2a-platform.example/ext/deal/v1`
- DataPartに `deal.rfp` / `deal.offer` / `deal.contract` / `deal.approval` を送受信
- 拡張は `A2A-Extensions` ヘッダで明示

## 11. 紛争解決（MVP）
- 納品後に合意できない場合は「紛争」ステータスへ遷移
- 管理者が **7営業日以内** に裁定
- 裁定結果は **全リリース / 部分リリース / 全返金** で確定
- 裁定は管理者画面で実施し、証拠・ログを参照して判断

## 12. 手数料（MVP）
- 代理店側から **10%** を徴収（支払いリリース時に差し引き）
- 最低手数料: **50,000円 / $300**
- 3,000,000円超は **8%**

## 13. KYC/KYB（MVP）
- 代理店: 会社情報、受取口座、実績サンプル2件
- 依頼側: 法人メール、会社情報（簡易）
- 200万円超は追加確認

## 14. SLA（MVP）
- 見積初回返信: **5営業日以内**
- 無応答: **7日で自動クローズ**
